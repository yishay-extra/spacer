# WP10 validation: AudioUnit hosting (needs a real Mac, third-party AUs, listening)

The host-independent logic is tested offline on Linux and macOS CI: slot
management, instance reuse across swaps and recalls, state (de)serialisation,
latency compensation (offline render alignment), bypass and insert crossfades,
the out-of-process scanner (real child process: crash, hang, blacklist,
dead man's pedal), and OSC / MIDI parameter paths. All of it uses a fake
in-process plugin format (`tests/engine/TestPlugins.*`). macOS CI also scans
Apple's AUDelay in process and with `spacer-plugin-scanner`, hosts it in a
source slot with an alignment check, and round-trips its state through a scene.

There is no plugin UI yet (insert slots, editor windows: WP11e). Until then,
put inserts into a project by editing the `.spacer` JSON (`"inserts":
[{"pluginId": "AudioUnit:Effects/aufx,dely,appl", "stateBase64": "",
"params": {}, "bypassed": false}]`).
List installed identifiers with `auval -a` (type,subtype,manufacturer ->
`AudioUnit:Effects/<type>,<subtype>,<manufacturer>`).

| # | Setup | Steps | Expected | Result |
|---|-------|-------|----------|--------|
| 1 | Spacer.app built by CI | Check `Spacer.app/Contents/MacOS/` | `spacer-plugin-scanner` is next to `Spacer` | |
| 2 | Several third-party AUs installed (including one known to be slow to scan) | Trigger a full scan (`PluginHost::scanAll`, UI in WP11e) | Every effect AU appears in `~/Library/Application Support/Spacer/plugin-cache.xml`; the app stays responsive enough (scan currently runs on the message thread; see PR) | |
| 3 | A plugin that crashes on load (or `kill -9` the scanner from Activity Monitor while it scans one) | Scan | That identifier is blacklisted with a reason; the app keeps running; a second scan skips it | |
| 4 | Project with a reverb AU on source 1 and a linear-phase / look-ahead AU (latency > 0, e.g. a FabFilter Pro-Q in linear phase, or a limiter with look-ahead) on speaker 1 | Play pink noise through two sources and both speakers; record the outputs | Sources stay sample-aligned and speakers stay sample-aligned (compare with a click track); latency in the status shows the plugin latency added | |
| 5 | Same project | Change a plugin setting that changes its latency (e.g. switch Pro-Q to zero latency) | The graph is rebuilt and alignment is restored within a second; one short crossfade is audible at most | |
| 6 | Scenes A and B with different reverb settings (capture with the plugin editor open, once WP11e exists; otherwise edit `stateBase64` by capturing in code) | Recall A ↔ B with 2 s transitions | Reverb settings switch with a 50 ms crossfade, no click, tail continues smoothly; parameters listed in `params` ramp over 2 s | |
| 7 | Project referencing an AU that is not installed | Open it | Project loads, a warning names the missing plugin and slot, the slot passes audio through | |
| 8 | Insert on a source; MIDI mapping to `source.1.insert.0.param.0`; OSC `/spacer/source/1/insert/0/param/0 0.5` | Move the controller / send OSC | The plugin parameter follows | |
| 9 | 16 sources each with one light AU, 32 speakers each with an EQ AU | Play for 10 minutes at 128 frames | No xruns attributable to plugin hosting; CPU in budget (depends on the plugins) | |
| 10 | Mono source with a stereo-only AU | Play | Signal is processed (fed dual mono, left output used) | |
