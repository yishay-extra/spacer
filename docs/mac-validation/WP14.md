# WP14 — manual validation of the integration pass on a real Mac

CI (Linux + macOS) covers the logic of every WP14 item with unit and offline
engine tests (see the PR, "What CI verifies"). This checklist covers what needs
a real device, real senders or a listener. Record pass / fail and notes for
each check.

## Setup

1. A Mac on macOS 12+ with the Spacer app built in Release (a Debug build for
   check 10).
2. An audio interface (or the built-in output) with at least 4 outputs, or
   headphones for the checks that only need a stereo pair.
3. A DAW that sends MIDI clock (Logic, Live or Reaper) to the IAC Driver.
4. A second machine or a script that sends OSC (`python-osc` or `oscsend`).
5. One AudioUnit with an editor (e.g. Apple AUDelay or AUGraphicEQ) and one
   with parameters you can see move (AUBandpass).
6. The demo project `resources/examples/stage-demo.spacer`, with a file source
   added (any 10 s+ WAV) and a second scene where that file source uses
   another spatializer.

## Checks

### 1. OSC motion parameters and file transport

Send `/spacer/source/1/motion/radius 3.0` to an orbiting source, then
`/spacer/source/<file id>/file/play`, `.../file/seek 2.0` and `.../file/stop`.

Expected: the orbit widens with no jump in its position along the circle
(no phase restart), and the file plays, seeks and stops. The OSC stats show no
"unsupported" count.

### 2. Sample-accurate OSC bundle timetags

Send two bundles with timetags 100 ms apart, each setting
`/spacer/source/1/mute` on and off, against a constant generator source.
Record the output with a second interface (or loop back into a DAW).

Expected: the mute edges are exactly 100 ms (4800 samples at 48 kHz) apart,
±1 sample, regardless of the 30 Hz UI tick. Note: the absolute time is the
callback time of that sample (the device output latency is not added).

### 3. MIDI bare paths follow the selected source

Map a CC to the bare path `gain` (no `source.<id>.`), select another source in
the Sources panel and move the controller.

Expected: the gain of the selected source changes.

### 4. Live modulator edits

Give an orbit an LFO modulator on `motion.radius` (period 2 beats). While it
runs, change its depth, then its period, then add a second modulator.

Expected: no audible jump or phase restart of the LFO or of the orbit on any
of these edits; removing a modulator does rebuild (a 50 ms fade is fine).

### 5. Period edit re-anchors

Change the orbit's period from 4 to 8 beats while it plays.

Expected: the source continues from where it is (no jump), at half the speed.

### 6. File source crossfade on recall

Recall the second scene (file source on another spatializer) while the file
plays, with 0 s transition.

Expected: a smooth 50 ms crossfade between the two renderings; no gap, no
restart of the file, no click.

### 7. Device change keeps the cue position

Arm a cue list, go to cue 3, recall a scene from OSC, then change the buffer
size in Settings.

Expected: after the device restarts the cue list is still at cue 3 (the next
Go fires cue 4), and the sound is the recalled scene's (not the state before
the recall).

### 8. External clock latency compensation (needs the DAW)

Follow the DAW's MIDI clock. Put a click on beat 1 in the DAW and an `AtBeat`
cue in Spacer that switches a generator impulse on at the same beat. Record
both in the DAW (Spacer through a loopback or a second input).

Expected: with trim 0 the Spacer event lands within ~1–2 ms of the DAW click
(automatic: device output latency + 1.5 ms limiter look-ahead are compensated).
Adjust "Clock latency trim" in Settings until they align; the change applies
without the clock relocking. Record the trim needed for this interface.

### 9. Ambisonic vs VBAP level on a horizontal ring

On an octagon (or quad), place a VBAP source and an Ambisonic source (order 3)
with the same pink generator at the same position, and solo each in turn.

Expected: both read the same level on the speaker meters (within ~0.3 dB),
also when the ambisonic source's spread is raised. Setting
`"ambisonics": {"order": 3, "maxRe": false}` in the project file changes the
ambisonic image (narrower main lobe, more side lobes) and still loads.

### 10. Plugin editor edits

Open an AU editor on a source insert, turn a knob, then check the title bar /
Save state; with installation mode on and autosave at 60 s, wait for an
autosave and open the `.autosave.spacer` file.

Expected: the project shows as modified after the knob edit (not after OSC or
modulator changes to that plugin); the autosave contains the new plugin state.
With a Debug build, the allocation guard stays silent through checks 1–7.

### 11. Speaker-chain override in the layout table

Add an insert to a speaker (creates its speaker chain) and give that chain
another trim in a scene; open the layout editor.

Expected: the speaker's Trim, Delay and Pol cells show the chain's values with
"(chain)", in blue, read-only, with the layout value in the tooltip.

### 12. Modulator sources from OSC and MIDI

Give a source a modulator `osc{"/mod/x"}` on `spread` and one `midi{cc 20}` on
`gain`; send `/mod/x 0.8` and move CC 20 to 0.

Expected: spread follows the OSC value, the gain modulation follows the CC
(also at value 0).
