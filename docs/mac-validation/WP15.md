# WP15 — manual validation of the 3D stage view on a real Mac

CI (Linux + macOS) covers the maths and data behind the 3D stage view with unit
tests in `tests/ui/`: `StageTransformTests`, `StageHitTestTests`,
`StageDepthTests`, `StageSharesTests`, `StageCloudTests`, `StagePaletteTests`,
`StageSceneTests` and `PaintStatsTests`. This checklist covers what needs a
real screen and a real mouse: how the drawing looks, how dragging feels, and
the paint time. Record pass / fail and notes for each check.

## Setup

1. A Mac on macOS 12+ with the Spacer app built in Release.
2. An audio output (the built-in output is enough).
3. The demo project `resources/examples/stage-demo.spacer`.
4. For check 10, a project with 64 sources on a 32-speaker layout, and the
   paint-time readout turned on by starting the app with
   `SPACER_STAGE_STATS=1 /path/to/Spacer.app/Contents/MacOS/Spacer`.

## Checks

### 1. 3D rotation

Open the stage. Drag empty space in every direction, including down until you
look at the layout from underneath.

Expected: the stage opens in 3D; dragging rotates the view; the floor stays
level (no roll); looking from underneath works.

Result: pass / fail — notes:

### 2. Top, Side and Front snaps

Press Top, Side and Front in turn.

Expected: Top and Side show the same positions as the previous top and side
views; in Front, the right of the room is on the right of the screen.

Result: pass / fail — notes:

### 3. Heights on Dome 22

Load the Dome 22 layout.

Expected: every speaker above the floor has a stem to the floor; the heights
of the three rings are readable.

Result: pass / fail — notes:

### 4. Dragging speakers in the layout editor

Drag a speaker in Top, then in Side, then in free 3D.

Expected: the table values follow each drag; ⌘Z undoes each drag as one step.

Result: pass / fail — notes:

### 5. Colour and cloud density

Play `resources/examples/stage-demo.spacer`.

Expected: each source has its own colour; a louder source has a denser cloud;
a silent source is a dot.

Result: pass / fail — notes:

### 6. VBAP hand-over

Watch an orbiting VBAP source.

Expected: the lines and the speaker clouds hand over from speaker to speaker
as it moves.

Result: pass / fail — notes:

### 7. DBAP, Direct and Ambisonic sources

Look at a DBAP source, a Direct source (to two speakers, one of them an LFE)
and an Ambisonic source.

Expected: DBAP shows many faint lines; Direct shows lines to exactly the
listed speakers; Ambisonic shows the cloud only.

Result: pass / fail — notes:

### 8. Muted source

Mute a source.

Expected: it is drawn grey, with no cloud.

Result: pass / fail — notes:

### 9. Solo and drag in free 3D

Click a speaker (solo pink noise), then drag a source in a freely rotated 3D
view.

Expected: both still work; the drag moves the source in the screen plane.

Result: pass / fail — notes:

### 10. Paint time

Open the project with 64 sources on a 32-speaker layout, started with
`SPACER_STAGE_STATS=1`. Let it run with sound for a minute while rotating.

Expected: the caption shows the paint time; record mean and max. Budget: mean
at most 8 ms.

Result: pass / fail — mean: ___ ms, max: ___ ms, notes:

### 11. Snaps on a layout with height

On Dome 22, press Top, Side and Front.

Expected: in Side and Front the floor is a single line and the mast shows
height; labels stay readable.

Result: pass / fail — notes:
